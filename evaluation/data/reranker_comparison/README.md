# U06 固定候选池重排对照

本项目中文 RAG 使用 Qwen Embedding＋BM25＋等权 RRF，适用范围过滤在候选截断前执行。维护者在 U05 后明确采用 Hybrid；U05 原消融及当时默认判断保留。

本轮对照复用35段公开中文知识与60条已见固定题（52可答＋8诊断），不改旧正文或 gold。原问题在同一 Hybrid 索引召回20条，保存完整候选、顺序、来源、hash，再关闭编码进程。RRF原序、原生成式排序和专用评分都使用这个固定池，最终交付top5；不启用改写或补检。此处20条固定池不表示扩大生产普通5／支持20的原召回预算。

## 固定模型与输入

- 专用模型：[Qwen3-Reranker-0.6B](https://huggingface.co/Qwen/Qwen3-Reranker-0.6B/tree/e61197ed45024b0ed8a2d74b80b4d909f1255473)，Apache-2.0；官方固定五文件大小及SHA在mcp/qwen_reranker.py。CPU float32、4线程、batch=1、最多1024 token。复用已有data/embedding-env依赖与锁，不修改主环境。官方yes/no末位置评分，不生成JSON索引，也不调用外部API；分数不是校准后的正确率。
- 生成式：现有deepseek-flash、生产build_rerank_prompt、temperature=0、max_tokens=8192、1轮；输入沿用标题80／正文160字的预览。原始响应、usage及原解析行为单独保存，不静默修复重复／缺项。
- 专用模型读标题和完整正文，超过token上限截断并计数。两路候选相同，但正文输入长度不同；结果属于可部署配置对照，不能将全部差异归因于架构。
- 本地评分2轮；先单独记录加载和预热，再记录每查询重排延迟（含进程通信）。生成式含网络和远端推理。RRF原序无额外模型重排，不用0ms冒充完整检索耗时。

## 复现

先按项目README准备Redis、Chroma与Qwen Embedding，以及evaluation/embedding_requirements.lock对应的独立推理环境。显式准备重排模型（约1.2GB；运行时不自动下载）：

```powershell
uv --no-cache run --locked --offline python -m evaluation.run_reranker_comparison --prepare-model
```

真实生成式对照会产生API费用，需自行配置官方deepseek-flash的环境变量。每次请求都经统一SQLite账本，按核对的峰值输入2／输出8元每百万token保守结算，当前脚本本轮上限¥5、禁用隐式重试。输出目录必须全新，已付费账本拒绝重复运行；费用预算属于整个本轮，不能换目录重置额度。

```powershell
uv --no-cache run --locked --offline python -m evaluation.run_reranker_comparison --live --output data/evaluation/u06/comparison-v1
```

## 指标与边界

AEH按必需证据组计算，Recall按qrel≥2段计算；分级nDCG使用2^grade−1与log2位置折扣。先报告20候选池覆盖上界，再报告top5的AEH／Recall／MRR／nDCG；dev、已见test、support与诊断分列。必要证据不在池中属于召回缺失，不归罪重排。

生产生成式路径对缺项、重复、bool和越界索引拒绝为有效排序，保留原候选顺序并诊断；专用路径校验分数数量和有限数，失败也保留原序，不额外付费回退。分数并列保留原顺序，原来源元数据保留。知识不足不由模型生成新政策，订单事实仍走业务工具。

这些题已被用于项目开发，规模小且语料为35段；不能宣称独立泛化或生产SLA。GPU、并发、真实最终答案质量、本轮未见集均不在本次验证范围。新增补检与自适应策略另做独立消融。

## 本轮结果

以下为35段、52条已见可答题的固定20候选池质量对照；8条诊断不进入准确率分母。不是独立泛化或真实回答正确率。

| 配置 | AEH@5 | Recall@5 | MRR@5 | nDCG@5 | 必需证据组保留 |
| --- | --- | --- | --- | --- | --- |
| Hybrid原序 | 50/52（96.15%） | 0.9423 | 0.8526 | 0.8292 | 54/57 |
| 现有生成式排序 | 52/52（100%） | 1.0000 | 1.0000 | 0.9698 | 57/57 |
| Qwen专用评分 | 51/52（98.08%） | 0.9808 | 0.9519 | 0.9023 | 56/57 |

原20候选池Recall与AEH均100%。Qwen修复原序的授权边界题R-T01-02和排查／资格多证据题U04-S11，但新增R-D10-02漏项：复合问题同时询问追加退货确认与更换银行卡收款时，退款去向证据K05.P03被排出前五。该证据在候选池中，说明需要问题要素覆盖，不能靠扩大召回次数代替。

生成式共60次真实API请求，按usage及保守峰值单价结算¥1.711836；无HTTP失败、缺usage或费用上界违规。56/60条排序完整，4条耗尽8192输出token后无法解析，保留原候选顺序计分、不重试。3条为可答题、1条为工具诊断。Qwen本地首轮60/60评分完整、未发生截断；单独重排P95为13,157.386ms，生成式为39,575.966ms，不含候选召回和最终生成。第二轮60条排序与首轮逐题一致，P95=11,331.696ms；加载及预热13,533.648ms单列，均未发生截断。单重排进程峰值工作集2708.219MiB（约2.64GiB）、峰值私有提交3733.566MiB（约3.65GiB），不等于显存或两个模型的同时内存总量。

**当前默认Hybrid＋Qwen专用重排，生成式可显式选择llm。** U06首轮按质量不下降的冻结门槛保留生成式；维护者后续要求综合质量、重排时间和成本选择默认，项目据此采用Qwen。原实验门槛、未采用结论与原始结果保留，本次不是修改实验成绩。

Qwen相较生成式完整证据命中下降1/52（1.92个百分点），MRR下降0.0481、nDCG下降0.0675；平均重排耗时15.82秒降至10.21–10.99秒，降低30.5%–35.4%，P95降低66.8%–71.4%；排序完整率56/60升至60/60。该权衡面向当前项目的响应时间与本地部署目标，不宣称统计最优或独立泛化。生成式远端内存未测，不能比较总硬件效率。

本地重排需额外进程内存及加载预热；API费用为0不等于计算成本为0，也不能声称整体对话费用或P95有同等降幅。默认异常仍保留原候选顺序并诊断，不增加付费回退。多证据覆盖、补检和自适应策略不包含在这次默认切换中。
