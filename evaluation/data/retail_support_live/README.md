# T18 真实小样本对话脚本

本目录只保存 T18 的固定脚本用户、有限分支和判定口径。它不是用户模拟器平台，也不是新的业务资料；运行器直接调用生产 `RetailService`，脚本用户只根据真实可见回复、已展示待确认详情和 Host 事件推进。

当前脚本为 `t18.2`：离线修复完成反馈／人工请求后的终止，以及退款去向问答。首次 `t18.1` 的真实结果、费用和脚本无效判定保留，修复不代表已做新的真实对话。

## 文件

- `cases.json`：S01—S04 的完整用户原文、有限澄清、重启点、确认门槛和预期业务状态。
- 运行器：`evaluation/run_retail_support_live.py`。
- 定向测试：`tests/test_retail_support_live.py`。

## 固定顺序

`S01A、S01B、S02B、S02A、S03A、S03B、S04B、S04A`，每组每案一次，共 8 条正式对话。S01 这一对同时作为真实烟测，进入主表并计费。不因首条结果替换后续任务或调整顺序。

## 脚本边界

- 只在真实回复包含可用且未重复的建议后推进到“已解决”或“人工”反馈。
- 退货确认只在完整、正确的待确认详情已于前一个独立用户轮展示后发送；准备与展示同轮、错误目标、未展示详情都不确认。
- 身份与目标最多各补充一次；达到用户轮上限即停止并记业务失败，不为失败模型补试。
- S03 在第一次出现未重复建议后关闭并重建 runtime／MCP，使用同一 SQLite、会话、事件日志和唯一账本；重启本身不产生业务写入。
- S01／S04 不提供退货授权；S01 无订单写入，S04 只有模拟人工交接事件。
- S01 发送解决反馈、S04 发送人工请求并接收回复后即结束；是否实际解决或成功交接由结果断言判断，不再发新一轮排查。
- S02／S03 仅在模型明确询问退款去向时回答一次“退回原支付方式”，这只是去向选择。仍须完整详情展示后的独立确认才允许提交；重复询问不会无限补答。
- S03 尚未选择退货时只补充排查信息，不提前进入身份／退款分支。
- 汇总保留 `execution_valid` 的正常结束含义，另以 `evaluation_valid` 计算有效分母；已有 `validity.json` 中 `script_valid=false` 的案例不会计入配对。

## 命令

运行器仍提供 `preflight`、`live`、`summarize`，均要求 `--run-id`。`preflight` 不调用收费模型；`live` 必须显式执行，使用累计5元的预算约束；`summarize` 会重新写入所选目录的汇总文件。

本次只授权离线修复，未授权付费补跑。不要对首次 `t18-support-20261020` 执行任何会写入证据或汇总的命令。后续复验须另行明确证据目录、重新冻结和原账本累计口径，不能通过新run重新获得5元，也不能覆盖首次结果。T17旧场景与资料保持原样。
